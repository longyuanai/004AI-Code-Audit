# 毕业设计演示与答辩准备

通用答辩草稿，学生、学校、导师和正式答辩时长待补充。建议演讲 8 至 10 分钟，
实际现场按学校安排调整。PPT 使用真实架构、数据库、截图和实验数据。

## 幻灯片顺序

1. 题目与本地 Python 审查范围。
2. 现有项目缺口和本次需求，保留原 CLI。
3. 实际架构及受限工作进程，不把进程分离称为沙箱。
4. SQLite 四表和静态/AI 数据分离。
5. 五类静态规则与已知变量追踪限制。
6. 真实界面和本机 Qwen 3B 复核。
7. 上传、路径、超时、XSS 与数据库回滚。
8. 20 个标注样本，三次静态与三次 AI 对照。
9. 误报漏报与 AI 无指标提升的实际结论。
10. 独立离线部署、已验证测试及限制。
11. 演示步骤与后续改进。

## 现场演示

先按部署手册启动并确认 Ollama 已有模型可用。在界面导入受控 calculator.py，
开始扫描并展示 CG-PY-004、文件位置和证据。勾选同意后展示真实模型、解释和
静态建议，点击导出 HTML，再刷新查看历史。

导入 ast.literal_eval 修复示例重新扫描，显示零发现并说明“零发现不代表安全”。
展示已保留的模型不可用测试报告，现场如需演示降级，用新数据目录、空的
LLM_PROVIDERS 启动第二个回环端口。不要为演示关闭系统安全措施、删除数据库或
执行上传代码。离线安装包和真实截图可作为现场网络/模型故障的说明证据。

## 常见问题与回答要点

| 问题 | 依据真实实现回答 |
|---|---|
| 为什么选 Python 标准库与 SQLite | 本地单用户流程规模有限，复用已有项目且没有新增生产框架依赖 |
| AST 是否能证明漏洞 | 不能；只匹配有限语法模式，变量追踪、作用域遮蔽和跨文件路径仍有局限 |
| 为什么静态与 AI 分开保存 | 模型失败或误判时原始依据仍可追溯，AI 判断不是人工确认 |
| AI 是否提升准确率 | 本次 20 例三轮对照没有提升，Precision/Recall 均为 80%，不能扩大结论 |
| 为什么模型不扫描漏报样例 | 本版复核静态候选，缺失候选不会送模型，需要改进静态覆盖 |
| 凭据会发到模型吗 | 常见形式脱敏且明确同意，但脱敏不是全语言完备证明；演示仅用合成凭据 |
| ZIP 如何防护 | 路径/链接/大小/数量/压缩比校验，逐条受限读取，不调用 extractall |
| 能公网部署吗 | 当前只监听回环，无账号和多用户授权；公网需要重新评估隔离与访问控制 |
| 能否自动修复 | 没有执行修复代码的功能，建议由开发者审查 |
| 测试数量是否等于准确率 | 不等于；工程测试验证行为，20 例实验才按标签计算指标，样本仍有限 |
